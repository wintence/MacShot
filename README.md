# MacShot

Скриншоты окон в стиле macOS для Windows. Окно снимается без системной тени,
обрамляется мягкой тенью и скруглёнными углами, кладётся на фон — и сразу
попадает в буфер обмена.

Это не скриншот экрана, а именно окна: в кадр не попадают ни курсор, ни другие
окна, ни то, что находится за окном.

Работает в трее, запускается горячей клавишей, живёт тихо.

## Что умеет

- **Захват отдельного окна** — привычным `PrintWindow`, без перекрытий и без системной тени Windows
- **Выбор окна курсором** — экран затемняется, окно под курсором подсвечивается, клик снимает
- **Буфер обмена** — снимок копируется сразу, без диалогов сохранения
- **Оформление** — фон (цвет, градиент под углом или своё изображение), отступ, тень
- **Тень подстраивается сама**: на тёмном фоне она светлая, на светлом — тёмная
- **Палитра цвета** — 29 готовых свотчей плюс системный диалог для своего цвета
- **Горячая клавиша** — любая комбинация, задаётся в настройках
- **Автозапуск** при входе в Windows
- **Русский и английский** языки интерфейса
- **Тёмная тема** окна настроек

Внешних зависимостей нет — только WPF и Win32.

## Требования

- Windows 10 версии 1809 или новее
- .NET 8 Desktop Runtime

## Установка

Скачайте `MacShot-full.exe` из [Releases](https://github.com/wintence/MacShot/releases),
положите в удобное место и запустите двойным кликом. Установка не нужна.

Файл весит около **64 МБ**, и это почти целиком не программа, а среда
выполнения .NET, упакованная внутрь. Подробно — в разделе
[«Почему файл такой большой»](#почему-файл-такой-большой).

## Почему файл такой большой

Сама программа — примерно **800 КБ**. Остальное занимает .NET, без которого
экранный интерфейс на C# работать не может.

Чтобы приложение запускалось на любой машине, рантайм .NET нужно носить с
собой — он и лежит внутри файла. Вот из чего складывается размер:

| Состав | Примерно |
|---|---|
| .NET 8, WPF, Windows Forms | ~62 МБ |
| Сжатие | отнимает примерно вдвое |
| Сама программа и иконки | ~1 МБ |

Сжатие уже включено в сборку. Уменьшить файл сильнее нельзя:

- **`PublishTrimmed` (обрезание неиспользуемого) к WPF неприменимо.** Обрезка не
  знает про рефлексию XAML и про то, какие конструкторы вызывает разметка.
  Окна продолжают открываться, но падают при первом обращении к типу из
  разметки — то есть в самый неподходящий момент.
- **`PublishReadyToRun` наоборот увеличивает** файл: он заранее компилирует
  IL в машинный код ради быстрого старта.
- **Языковые пакеты** уже отброшены, кроме русского.

Чтобы получить файл в 20 раз меньше, нужно отказаться от автономности:
собрать без рантайма и поставить на машину [.NET 8 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/8.0).
Такая сборка весит около 0,8 МБ, но требует отдельного шага установки, а на
чистой Windows без интернета её поставить нечем. По этой причине в Releases
выложена автономная версия.

Оба варианта собираются из одного и того же кода:

```powershell
# автономная, ~64 МБ — то, что лежит в Releases
dotnet publish -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:EnableCompressionInSingleFile=true -p:SatelliteResourceLanguages=ru `
  -o release-full

# компактная, ~0,8 МБ — нужен .NET 8 на машине
dotnet publish -c Release -r win-x64 --self-contained false `
  -p:PublishSingleFile=true -p:SatelliteResourceLanguages=ru `
  -o release
```

## Как пользоваться

1. Нажмите горячую клавишу — по умолчанию `Ctrl+Shift+8`.
2. Экран затемнится, окно под курсором подсветится.
3. Кликните по нужному окну — снимок окажется в буфере обмена.
4. `Esc` — отмена.

Дальше вставьте снимок куда угодно.

Программа живёт в трее. Правый клик по значку:

- **Снять окно** — запустить выбор окна
- **Настройки** — фон, отступ, тень, горячая клавиша, язык
- **Выход**

## Настройки

| Параметр | По умолчанию |
|---|---|
| Фон | градиент из двух цветов |
| Отступ | 40 |
| Тень | включена: размытие 36, сдвиг вниз 16, плотность 0.45 |
| Горячая клавиша | `Ctrl+Shift+8` |
| Язык | русский |
| Сохранять копию в «Изображения» | выключено |
| Запускать при входе в Windows | выключено |

Скругление углов не настраивается: радиус фиксирован, как в macOS.

Цвет берётся из палитры — рядом с каждым полем цвета есть образец, клик по
нему открывает палитру.

## Где лежат файлы

| Что | Путь |
|---|---|
| Настройки | `%AppData%\MacShot\settings.json` |
| Журнал | `%AppData%\MacShot\MacShot.log` |
| Снимки (если включено) | `%Pictures%\MacShot` |

## Как это устроено

```
App.xaml.cs                 разбор ключей, запуск, защита от второго экземпляра
Interop/                    P/Invoke и буфер GDI
Capture/                    поиск окна, PrintWindow с резервом на BitBlt, обмен пикселями
Render/                     скругление углов и сборка кадра: фон + окно + тень
Services/                   горячая клавиша, буфер, трей, автозапуск, журнал
UI/                         оверлей выбора, настройки, палитра, диалог клавиши
Lang/                       переводы интерфейса
Settings/                   модель настроек и разбор цвета
```

### Захват

Сначала `PrintWindow` с флагом `PW_RENDERFULLCONTENT` — он рисует окно в
переданный буфер и не зависит от того, перекрыто ли окно другими.

На окнах DirectComposition (Chromium, Electron, часть игр) `PrintWindow` уходит
в бесконечное ожидание. Поэтому вызов идёт в отдельном потоке с таймаутом, а
если окно не ответило — capture переходит на `BitBlt` с экрана.

Печатается всё окно целиком, по границам `GetWindowRect`, а потом кадр
обрезается до видимых границ DWM. Если сразу рисовать в буфер размером с
видимую область, содержимое смещается на ширину невидимой рамки.

### Отрисовка

Кадр собирается в `RenderTargetBitmap`: фон, поверх окно со скруглением и
тень через `DropShadowEffect`. Цвет тени выбирается по светлоте фона — на
тёмном фоне чёрная тень не читается, и окно приклеивается к подложке.

## Известные ограничения

- Скругление и тень рисуются сглаженно; на некоторых углах при увеличении
  может быть заметна «ступенька» в один пиксель
- Захват идёт в логическом масштабе окна. На смешанном DPI снимок может
  отличаться от того, что видно на экране
- При таймауте `PrintWindow` рабочий поток остаётся висеть вместе с буфером
  GDI; освобождается при выходе из процесса
- Перекрытые окна снимаются через `PrintWindow`. Если приложение не отдаёт
  содержимое (защищённый DRM-контент), кадр получится пустым
